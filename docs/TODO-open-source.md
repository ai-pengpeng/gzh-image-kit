# 开源发布检查清单

> 这份清单记录 `gzh-image-kit` 从内部产线剥离到开源版时，必须逐项确认的事。
> **发布标准：下表全部勾完，且 `grep` 复扫零命中。**
>
> 本文件**只记结论，不记过程**：内部路径、账号信息、凭据位置一律不写进仓库
> （这几类信息出现在这里，本身就是一次泄露）。

## 一、品牌词与个人信息

- [x] 各脚本的品牌串改为中性默认值，需要时由参数注入（`--account`、`GZH_IMAGE_KIT_BRAND`）
- [x] 页脚 / 刊头模板不再写死号名，重编号正则改为品牌无关
- [x] 注释与报错文案里的内部仓库目录名、内部路径全部清除，改为本仓库相对路径
- [x] 内部平台名（生图工具、编辑器产品名）改为中性表述
- [x] 内部案例细节（具体批次、具体标题）从注释里删除，只留判据
- [x] 作者署名与「原文出处」锚点保留（这是版权与来源信息，不是内部信息）

## 二、字体许可（合规硬项）

- [x] 5 个出图工具不再硬编码系统专有字体路径 → 统一走 `fontkit.py`
- [x] `fontkit.resolve_font()` 找不到可用中文字体时抛 `FontNotFoundError`，**绝不静默回退**
- [x] `fontkit.load(size, bold)` 处理可变字体（VF）字重实例化，避免整套图静默落在常规字重
- [x] README 补「字体配置与许可」小节，说明为什么不自带字体
- [ ] examples 里的示例图必须用**可再分发字体**渲染（待补齐样张后逐张确认）

## 三、环境参数化

- [x] Chrome 路径改为 `CHROME_PATH` / `--chrome` + 常见路径自动查找 + 清晰报错
- [x] 全部出图工具统一 `--out`，仓库内无写死盘符
- [x] `check.py` 不再依赖内部 `app.core.spec`（导入失败退回中性默认值）

## 四、指路准确性

- [x] 所有报错文案里引用的文档路径，在仓库里**真实存在**（`docs/配图标准.md`）
- [x] 报错里提到的修复工具，要么在仓库里，要么明说「该步骤未开源」并给替代做法
- [x] 失败提示回显用户实际敲的命令，不写死内部目录结构
- [x] 出图脚本自动创建输出目录，不在渲染完成后才因目录缺失失败
- [x] `--channel` 真正参与分派，不再是死参数
- [x] 非贴图渠道也有整组图片体检入口（`--images` 不带 channel）

## 五、发布前复核

- [x] 全部 `.py` 通过 `py_compile`
- [x] 每个工具 `--help` 可独立执行（`exit=0`）
- [x] 敏感词复扫（品牌名、内部代号、本机盘符、平台名）零命中
- [ ] `examples/` 放效果样张（1 套卡组 + 1 张步骤图 + 1 组插画渠道样张）
- [ ] README 每个工具补示例命令
- [ ] `git tag v0.1.0`

## 六、可重复执行

- [x] 本清单的每一项都能用一条命令复核（`grep` / `--help` / `py_compile`），不依赖记忆

> 判据：**如果一条规则只能靠人记，它就不算落地了。**
> 同样的话在 `docs/配图标准.md` §八里也写着——因为这条原则同时管代码和文档。
