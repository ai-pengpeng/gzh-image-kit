# 配图标准 · v0.1

> 这是本仓库所有出图脚本共同遵守的判据。代码里的每条守卫都能在这份文档里找到依据，
> 反之，文档里写的每一条都应该能在 `check.py` 或渲染器的断言里找到落点。
>
> **适用**：公众号贴图（竖版图卡）、正文配图、步骤图、封面。

---

## 一、画布与比例

| 比例 | 尺寸 | 工具 | 说明 |
|---|---|---|---|
| **3:4（推荐）** | **1080 × 1440** | `gen_cards.py`（默认） | 竖版信息流**满幅显示、无留白** |
| 1:1（备选） | 1080 × 1080 | `gen_cards.py --ratio 1:1` | 能发；竖版信息流里上下会被留白 |

| 项 | 值 |
|---|---|
| 安全边距 | 左右 ≥100px，上下 ≥80px（文字不出血） |
| 导出 | PNG，单张 ≤10MB（多数平台单图上限） |

**为什么推荐 3:4**：竖版卡片在信息流里是满幅展示，1:1 方图上下会留白，观感打折。
3:4 原生满幅，读者滑到即铺满屏幕。

## 二、配色

### 2.1 一套图内统一分组

按内容分组切换背景 + 强调色，读者一眼分辨「情绪 / 原因 / 解法 / 收尾」。
分组数量按内容定，**一套图内不要出现两套语义**（比如同一批里既用青色表示解法、又用青色表示问题）。

### 2.2 配图配色必须跟随封面（见 §10.5）

同一篇文章的正文配图与封面不同色系，读者会读成「两篇文章的图」。

## 三、字体与字号

### 3.1 最小字号红线（优先级高于下面所有分级）

**任何文字，在任何画布上，换算到手机屏幕后不得小于 12 CSS px。1080 逻辑画布下即 ≥36px。**

这条是硬红线，所有分级字号都必须服从它。只规定「每一级用多大」而不规定「最小不得小于多少」，
形态一变（比如加底部黑条、加页脚），小字就会自己掉到下限以下，没人拦。

**换算公式**（画布尺寸会变，所以标准必须写成可换算的形式）：

```
图片字号(px) = 目标屏幕字号(CSS px) × 画布宽度 / 360
```

360 是基准屏宽（安卓最常见 360dp；iPhone 是 390pt 更宽，所以按 360 算偏保守，安全）。

| 层级 | 屏幕等效 | 1024×1365 | **1080×1440** | 2160×2880 (2x) |
|---|---|---|---|---|
| hero 主视觉 | ≥40 | ≥114 | **≥120** | ≥240 |
| 要点 / 正文（读者要逐字读） | ≥15 | ≥43 | **≥45** | ≥90 |
| 辅助说明（副标、注释、来源） | ≥12 | ≥34 | **≥36** | ≥72 |
| 元信息（页脚、页码、眉标） | ≥12 | ≥34 | **≥36** | ≥72 |

**为什么下限是 12 而不是 11**：中文笔画密度比拉丁字母高，同样字号下可读性更差，
所以不用 iOS 的 11pt 下限，对齐 Material 的 caption 12sp 再加中文余量。

> 动手前先算一遍：`36px ÷ 1080 × 360 = 12 CSS px`。这条公式是本仓库所有字号守卫的唯一依据，
> `dazi_kit.py` / `gen_cards.py` / `gen_diagram.py` 的下限都由它现算，不是写死的常量。

### 3.2 分级字号（3:4 / 1080×1440 基准）

- 分类标签：**40px**（强调色）
- 标题主行：100px / 副行 68px
- 金句：84px（带引号内联，避免压字）
- 底部说明：**40px**（灰，最多 3 行）
- 页脚：**36px**（灰，写你的号名）
- 眉标：**36px**

1:1 版按同一张换算表折算（1024 基准）：说明 ≥34、页脚 ≥34，不允许 28/30 这类值。

### 3.3 改字号带来的版式代价（必须一起调）

字号上调后高度会增加，**不许靠压缩行距或缩小边距来腾空间**，那是把问题挪个地方。

1. **页脚从 26 提到 36，底部黑条要加高**：黑条内容区高度 ≈ 页脚字号 × 2.2，不要沿用旧高度。
2. **装不下就删字，不要缩字号**：底部说明最多 3 行，超了改文案，不是改字号。
3. 版心边距不许因为字号变大而收窄，宁可减少一屏的信息量。

### 3.4 第二根红线：文字对比度

**字号达标不等于看得清。** 字号从 26 提到 36 之后，灰色副标仍然「发飘」——问题不在大小，在深浅。

实测色板（WCAG 相对对比度，对浅色底 `#FAFAFB`）：

| 用色 | 原值 | 对比度 | 判定 | 处置 |
|---|---|---|---|---|
| 黑 INK | `#121214` | 17.94:1 | ✅ | 不动 |
| 次级灰 GRAY | `#969BA2` | **2.68:1** | ❌ 连 3:1 都不到 | 改 `#696F77` → **4.86:1** |
| 深绿 GREEN_D | `#008A5E` | 4.20:1 | ⚠️ 差一点 | 改 `#007C4E` → **5.04:1** |
| 荧光绿 GREEN | `#00B67A` | 2.53:1 | ❌ 只能当大字号重音 | 改 `#00A46C` → **3.09:1**（≥3:1 即可） |
| 蓝 BLUE / 红 RED | — | 6.23 / 4.59 | ✅ | 不动 |

**判据**：小字（≤ 手机 14 CSS px）≥ **4.5:1**；大字（巨字 / 头条数字）≥ **3:1**。
取自 WCAG 2.1 AA，和字号红线用同一套「屏幕实际大小」口径。

**为什么 2.68:1 必须改**：那个灰是全部副标、付句、页码的颜色，用量最大。
2.68:1 意味着**在户外的手机屏上几乎融进背景**，字号再大也只是「更大的一团浅灰」。

**三层守卫**：

| 层 | 位置 | 作用 |
|---|---|---|
| ① 导入自检 | `dazi_kit._verify_palette()` | 色板里任一文字色 <4.5:1，**kit 导入即失败** |
| ② 调用守卫 | `_guard_text_color()` | 拿装饰色当文字色，出图前报错 |
| ③ 主动体检 | `check.py --card-fonts` | 扫脚本里的低对比度色值，只在画文字的行报 |

**装饰色白名单**：分隔线、胶囊底这类颜色只准画线、填色块，**当文字色直接报错**。
这条比写进文档管用——因为它是执行不了的错，不是提醒。

**改色板的边界**：只调深浅，**不换色相**。灰还是灰、绿还是绿，语义色规则一条不动。

### 3.5 字体文件：找不到就报错，绝不静默回退

所有出图脚本经 `fontkit.resolve_font()` 取字体。找不到可用中文字体时抛 `FontNotFoundError`，
**不会悄悄换成系统默认字体**——「图能出、只是悄悄换了字体」是最难发现的一类事故。

**可变字体（VF）注意**：若 `GZH_IMAGE_KIT_FONT_BOLD` 指向一个可变字体文件（如 `NotoSansSC-VF.ttf`），
该文件本身不区分常规 / 粗体两层，必须显式做 variation instancing 才能渲染出粗体。
`fontkit.load(size, bold=True)` 已内置这一步（优先按名字取 `Bold`，退化到按轴设 `wght=700`），
出图脚本一律走这个入口，**不要自己 `ImageFont.truetype(resolve_font(True), size)`**。

## 四、每张图固定元素

| 元素 | 规则 |
|---|---|
| 页脚 | 号名 + 分隔符，字号 ≥ 下限，灰色不用装饰色 |
| 页码 | 全组连续，不跳号；`check.py --images` 会查连续性 |
| 边距 | 左右 ≥100px、上下 ≥80px |
| 底板 | 深色底 + 亮色字，或浅色底 + 深色字，**同一组内不要混** |

## 五、断行与排版红线

### 字数容量（3:4 / 1080×1440）

- 标题主行 ≤ **8 字**，副行 ≤ **12 字**
- 金句 ≤ **18 字**（超过改文案或拆卡）
- 底部说明 ≤ **3 行**（每行 ≤ 20 字）

### 三条规矩

1. **按词断行，不按字断行**。中文没有空格，等宽折行会把「人工智能」劈成「人工 / 智能」。
   `gen_cards.py` 的 `wrap()` 已按词库贪心填行，标点并入当前行（避头点）。
2. **标点不另起一行**（避头点）。句号、逗号、右引号不能出现在行首。
3. **短句不居中**。可见字数 ≤18 字才居中，超过就左对齐——多行居中的左边缘是锯齿。

## 六、装饰线不得与内容带相交

一张图最多一条装饰线，且必须落在**静态区**（页眉 / 页脚留白里），
不得穿过文字带或图片主体。收口区靠间距分隔，不靠再加一条线。

判据：**去掉这条线，信息量是否变化？** 不变就删掉——空要用版式解决，不能用装饰填。

## 七、自检清单（每批出完逐张过）

- [ ] 最小字号：所有文字换算到手机 ≥12 CSS px（`check.py --card-fonts`）
- [ ] 对比度：小字 ≥4.5:1，大字 ≥3:1（同上）
- [ ] 页脚 / 页码字号没有掉到下限以下
- [ ] 一套图内配色统一，且正文配图跟随封面色相（`check.py --fig-hue`）
- [ ] 断行按词切，无标点孤行、无「人工 / 智能」式劈行
- [ ] 装饰线不与内容带相交
- [ ] 张数与体积符合目标渠道规格（`check.py --images`）
- [ ] 右下角无平台自动水印残留

## 八、这套标准怎么保证不再回退

数值写在文档里只是「有人说过了」，不是保证。真正的保证有三层：

| 层 | 机制 | 在哪 |
|---|---|---|
| ① 渲染时就拦 | 字号 / 对比度断言写在 `dazi_kit.py`，不合规**出不了图** | 导入与绘制阶段 |
| ② 出图后能查 | `check.py --card-fonts` / `--images` / `--fig-hue` 三档体检 | 命令行 |
| ③ 守卫能自证 | 每条检查带样本自检；规则抓不到样本时报「守卫失效」，而不是静默通过 | `check.py` 内 |

**「有一道自检」不等于「自检管住了」。** 所以每条规则都要能回答：它抓的是规则本身，
还是只是一份记得住的清单？后者一定会在下一次改版式时失效。

## 九、和内部产线的差异（给看过内部版的人）

本仓库是从一条真实运营的公众号产线剥离出来的开源版，差异只有两类：

1. **品牌词与个人路径已全部移除**——页脚品牌串、账号名、本机路径都不在仓库里，需要你自己用参数或环境变量注入。
2. **平台专属的收尾步骤未随仓库发布**——比如「抹除右下角平台水印」这一步依赖内部脚本，
   开源版请用任意图片编辑器覆盖右下角固定区域，`check.py --images` 会把它查出来提醒你。

判据本身（字号公式、对比度阈值、断行规则）与内部版一致，没有为开源版放宽任何一条。

## 十、视觉说服力：让人记住的六条机制

### 10.1 加工流畅性：眼睛不该重新校准

同一批图里字号、边距、行距跳变，读者每翻一张都要重新找焦点，于是什么都不记住。
**一套图一套参数**，变的只有内容。

### 10.2 隔离效应：一排一样的东西，一个都记不住

连续 5 张版式完全一样的卡，读者只记得第一张。需要区分的地方用「承载量」区分
（一张只说一件事 vs 一张给三条），不是靠加装饰。

### 10.3 具体性效应：形状和数字比形容词好加工

「快了 3 倍」比「显著提升」好记；「27 行代码」比「代码量很少」好记。
数字要有出处，没有出处的数字等于编造。

### 10.4 峰值-终值：图的头和尾必须单独设计

首张决定要不要看，末张决定记住什么。中间可以平，两头不能平。

### 10.5 一致性累积：配图配色必须跟随封面

正文配图与封面同色系，读者才会读成「同一篇文章」。
判据：配图主色相与封面偏差 **≤30°**。

```bash
python check.py --fig-hue cover.jpg fig1.png fig2.png
```

> 这条不是审美要求。配图跟封面撞色相时，读者的第一反应是「这图是从别处找的」，
> 整篇的可信度跟着掉。工具时代最容易犯的错就是「每张图各自好看，放一起不像一套」。

### 10.6 元规则：好看不等于加装饰

判断任何装饰（线、框、底色、符号）该不该留，只问一句：
**去掉它，信息量变不变？** 不变就去掉。空要用版式解决，不能用装饰填。
